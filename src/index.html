                    Personalization

                    Cover art

                    How covers are requested

                    Covers load straight from Marvel's image servers. The metadata service reports each address, but one naming any other host is refused before a request is made. This app stores only the address, never the image itself, and never proxies or re-hosts artwork. Switch covers off and every cover becomes a plain typographic tile, and no cover is requested at all.

                    Theme

                    What the choice affects

                    The choice is stored in this browser alongside your other settings and is never sent anywhere. High contrast mode and reduced motion are still honoured whichever you pick.

                    Connectivity

                    Metadata source

                    Why this can be changed

                    The default is the community API this was built against. If it disappears the upstream is self-hostable, so you can point this at your own copy.

                    About this app

                    An unofficial fan project

                    Not made by, endorsed by, or affiliated with Marvel or The Walt Disney Company. Marvel, Marvel Unlimited, and all related names, characters, and logos are trademarks of Marvel Characters, Inc.

                    Metadata and links only

                    No comic content is stored, copied, proxied, or served. The app tracks which issues you have read and links out to Marvel's own site and reader. Reading an issue requires your own Marvel Unlimited subscription. Cover images load directly from Marvel's own servers, and an address on any other host is refused rather than requested. Switching cover art off stops them being requested.

                    Where the metadata comes from

                    Issue, series, and creator metadata comes from the community marvel.emreparker.com API, built from emreparker/marvel-comics and originating with Marvel. The snapshot ends in 2025, so very recent issues may be missing. You can still add those by hand. The API base URL is configurable under Backup & settings.

                    Curated Reading Lists

                    Most bundled Reading Lists are put together in this project, some by a script from Marvel series metadata and some by hand; the rest are fetched from a community source. Each list in the catalog names its own origin and the date it was last updated.

                    Keyboard shortcuts

                    ↵Open the current issue in Marvel Unlimited
                    DMark it read and move to the next one
                    Ctrl + \Collapse or expand the sidebar, anywhere in the app

                    The two reading shortcuts pause while you are typing in a box, and ↵ leaves the button or link you are on to do its own job.

                    Your data

                    Everything you save lives in this browser, at this exact address: your lists, your reading progress and your notes. There is no account to create, and no analytics or tracking of any kind. Your progress and your notes are never sent anywhere. Clearing site data for this address erases them, so export a backup regularly.

                    What leaves this machine, request by request

                    What does leave this machine is the ordinary business of fetching what is on screen. Opening the app asks the metadata API named above whether it is reachable, which is what the status pill reports. Searching for issues sends what you typed, and so does asking an imported line to find its own match; searching the catalog, series or creators is answered from files already on this machine, but adding a whole series or a creator's issues then asks the metadata API for every issue it lists, which is the longest run of requests the app makes. Filling in details sends every issue number still missing them, across every list you keep, starting with the one you are about to read. Cover art is requested from Marvel's image servers as it appears, so those servers see which issues are on screen; switching cover art off stops them being requested at all. Those are the only servers a cover is ever asked of: an address the metadata API reports on any other host is refused before anything is fetched. Opening an issue asks the metadata API for the reader link when this copy does not already have it, then hands that one issue to Marvel's reader, or to marvel.com whenever no reader link can be resolved. Adding an issue by hand sends the words in the title box to the Marvel Fandom wiki, a community site Marvel does not run, and it does that only when you press the lookup button. That wiki then sees the title you searched for; your lists, your progress and your notes are no part of the request, and no picture is fetched from it.
